# HackMeridian submission integrity checklist

Based only on the submission-integrity rules supplied by the owner. This checklist is not organizer approval and does not verify eligibility or any unprovided event rules.

## Mandatory disclosures

- [ ] Confirm the actual event start/cutoff and starting point.
- [ ] Disclose all relevant prior work, including work outside this repository or at a regional activation.
- [ ] State specific new work delivered during HackMeridian in both README and demo.
- [ ] Link actual progress evidence; do not backdate commits or use file timestamps as event proof.
- [x] Meaningful OpenAI Codex code, visual and documentation assistance is disclosed in the README and draft deck.
- [ ] Confirm that attribution is complete for every tool, asset, template and external contribution the team actually used.
- [ ] Use consistent before/after and AI statements in README, submission form, video and deck.

## Required submission artifacts

- [ ] Add a real repository URL. Verify judges can access the code and setup instructions.
- [ ] Add a YouTube or Vimeo demo URL. Confirm duration is 2–4 minutes and judges can access it.
- [x] A self-contained HTML pitch-deck draft exists: [KARGA-PITCH-DECK.html](KARGA-PITCH-DECK.html).
- [ ] Complete the deck's team, baseline, event-progress and link fields; the current file is explicitly a draft.
- [ ] Verify the final deck file is PDF, PPTX, PPT or HTML and no larger than 20 MiB (20,971,520 bytes).
- [ ] Submit the actual deck file, not merely a local filesystem path or an unfinished outline.

A demo script is not the required uploaded video. A local folder is not the required repository URL. A localhost address is not a publicly accessible deployed app.

## Demonstration integrity

- [ ] Distinguish implemented code, automated test results, owner-reported operation and independently demonstrated live behavior.
- [ ] Show only genuine organizer-approved KP; label example/draft journeys clearly.
- [ ] Present carbon values as estimates, not verified reductions, credits or offsets.
- [ ] Label Testnet XLM as having no monetary value.
- [ ] Distinguish welcome wallet funding from the separate earned eco reward.
- [ ] Show a successful earned-payment confirmation only if it actually happened; otherwise state the integration/demo limitation.
- [ ] Keep private keys, passwords, database URLs and session/handoff tokens out of published materials.
- [ ] Remove or complete every TEAM TO CONFIRM / TEAM TO ADD marker before submission.
